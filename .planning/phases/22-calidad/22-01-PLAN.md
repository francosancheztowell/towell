<decisions>

**D1 — PHPMD sin baseline: ratchet por archivo contra su versión base.** Aplicar `codesize` "a secas"
a un archivo legado cambiado haría fallar a cualquier 19-xx que toque, por ejemplo, un controller de
1 400 líneas: eso es cobrar la deuda vieja a quien pasa por ahí. En su lugar, para cada PHP cambiado
se corre PHPMD sobre la versión base (`git show <base>:<archivo>`) y sobre la actual, y se falla solo
por **violaciones nuevas**, identificadas por `regla + clase + método` (no por línea, que se mueve).
Archivo nuevo = base vacía, así que todo cuenta. Consecuencias documentadas:
- Método privado sin usar nuevo en un archivo viejo → falla (clave nueva).
- Método legado que ya excedía 100 líneas y crece → no falla (misma clave; la deuda la paga su dueño).
- Método nuevo de 120 líneas o con complejidad 11 → falla.
- Renombrar un método que ya violaba → clave nueva → falla: renombrar es buen momento para partirlo.

**D2 — Umbrales PHPMD (`phpmd.xml`).**

| Regla (set) | Umbral | Por qué |
|---|---|---|
| `CyclomaticComplexity` (codesize) | `reportLevel` 10 | Default de PHPMD; McCabe clásico. |
| `NPathComplexity` (codesize) | 200 | Default; caminos de ejecución testeables. |
| `ExcessiveMethodLength` (codesize) | 100 líneas, `ignore-whitespace` | Default; los métodos gigantes de PT (600–800) son el caso a evitar. |
| `ExcessiveClassLength` (codesize) | 1 000 líneas, `ignore-whitespace` | Default. |
| `ExcessiveParameterList` (codesize) | 10 | Default. |
| `ExcessiveClassComplexity` (codesize) | 50 | Default (WMC). |
| `UnusedPrivateField`, `UnusedPrivateMethod` (unusedcode) | — | Lo mismo que phpstan ya marca, pero sin baseline. |
| `UnusedLocalVariable` (unusedcode) | `allow-unused-foreach-variables` | Los `foreach ($x as $k => $v)` que solo usan `$v` son idiomáticos. |

Fuera, a propósito: `UnusedFormalParameter` (Laravel/Excel imponen firmas: `styles(Worksheet $sheet)`,
`handle($request, $next)`, closures de eventos), `TooManyMethods`, `TooManyPublicMethods`,
`TooManyFields`, `ExcessivePublicCount` (controllers y modelos de Laravel las disparan por diseño).

**D3 — Archivos cambiados: una sola lógica.** El cálculo de la base del paso de Pint (PR → base
del PR; push → `before`; rama nueva o force-push → `HEAD~1`) sale a `scripts/php-cambiados.sh`, que
usan Pint, PHPMD y `composer quality`. Localmente (sin variables de GitHub) la base es
`git merge-base HEAD ${CAMBIADOS_BASE:-origin/main}` comparada contra el árbol de trabajo, así que
incluye lo no commiteado. Con `--base` imprime solo la base (PHPMD la necesita para `git show`).

**D4 — Métricas nuevas del ratchet.**
- `catch vacío`: `catch (…) { }` con cuerpo vacío (sin comentario) en `app/**/*.php`. Hoy 29. Las
  excepciones deliberadas del CONTEXT (Monitoreo, ErrorRecorder, TelemetriaController,
  EnsureModulePermission, Navegacion) cuentan igual; simplemente nadie las baja.
- `duplicación %`: `jscpd` (devDependency) sobre `app`, `resources`, `routes`, `config`, `database`,
  `public/js`, `scripts`, `tests` con formatos php, typescript, javascript y blade; ignora `vendor`,
  `node_modules`, `public/build`, `tests/fixtures`, `*.min.js`, `storage`. Config en `.jscpd.json`
  para que `npx jscpd` a mano mida lo mismo. Se guarda con 2 decimales; techo = lo medido en la rama.
  Corre en `main()` (proceso aparte), no en `measure()`, para que `tests/Js/ratchet.test.mjs` siga
  instantáneo. `--top 'duplicación %'` lista los pares más grandes.

**D5 — composer audit.** Paso propio en el job `php`: si `composer.lock` está entre los archivos
cambiados (misma base de D3) → `composer audit --locked --abandoned=report` bloquea; si no, se corre
igual y un fallo sale como `::warning::` sin romper el job.

**D6 — `composer quality`** = `pint --test` (cambiados) → `phpstan analyse --memory-limit=2G` →
`phpmd` (cambiados, D1) → `npm run ratchet`. Documentado en CLAUDE.md §Commands y §CI.
PHP Insights no entra (ni como gate ni como script).

**D7 — Exports Urdido/Engomado: base abstracta + variante de 1 dato.** `BpmProcesoExport` y
`ReporteResumenSemanalProcesoExport` (abstractas) llevan todo el código; `BpmUrdidoExport`,
`BpmEngomadoExport`, `ReporteResumenSemanal{Urdido,Engomado}Export` quedan como subclases que solo
declaran el proceso (`'Urdido'`/`'Engomado'`), del que salen título de hoja, nombre de tabla y
encabezado `A1`. Mismo nombre y constructor: **los llamadores no se tocan**.
Red: test de snapshot que genera los 4 xlsx con datos fijos y compara celda a celda (valor, número
de formato, fuente negrita/color/tamaño, relleno, alineación), anchos de columna, celdas combinadas,
tablas, panel congelado, título y gráficas (nombre, posición). El snapshot se genera y se commitea
**antes** de refactorizar (commit propio) y el mismo test pasa después sin regenerarlo.

**D8 — ReqModelosCodificadosImport.** Tests primero (commit propio), luego: borrar `convertToInt` e
`isValidTotalValue` (22-02) y el catch vacío de `AfterImport` (fija `status = done` y los errores
en caché: flujo principal) pasa a `report($e)`. `catch vacío` baja 29 → 28 y se fija con `--update`.

**D9 — Cobertura (22-04).** `php8.4-pcov` local (apt), `php -d pcov.enabled=1 vendor/bin/phpunit
--coverage-clover` en esta rama; un script efímero (scratchpad, no se versiona) cruza clover
(líneas, cobertura y complejidad por clase) → riesgo = `ncloc × complejidad × (1 − cobertura)`.
La tabla de los 20 peores va a 22-01-SUMMARY.md con su dueño (track). El CI sigue con `coverage: none`.

</decisions>
